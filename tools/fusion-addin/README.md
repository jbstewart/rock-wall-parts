# RWF Check & Post — Fusion add-in

Checks a plasma setup against the shop rules **inside Fusion, before anything posts**, then posts it.

Every rule here exists because the mistake actually happened. The defects it was built from, all from one evening on `arcdroid-coupons`: a stale 1.2 mm tool arriving via an operation template; holes cutting clockwise in a setup with no model; operations left on the `Default` preset; a 3-operation program posted as 1 operation, twice; a relative-size stock box padding the blank by 0.04".

## Why it runs in Fusion and not against the posted file

A post processor only ever sees the operations it was handed. `getNumberOfSections()` is the posted selection, so a setup sheet reporting "Operation 1/1" cannot tell you the setup holds three — the unposted ones are not in its input at all. `Setup.allOperations` *is* that count, and it includes operations buried in folders and patterns.

There is also no post event in the Fusion API — nothing fires when you post. So this replaces right-click → Post Process rather than adding a step you have to remember. The check is the post button.

## Install

Shift+S → **Add-Ins** tab → **+** → point it at `tools/fusion-addin/RWFPostCheck` in this repo → tick **Run on Startup**. Nothing is copied outside the repo, so the add-in is versioned with everything else. It adds one button to the Manufacture ribbon's ACTIONS panel.

## Layout

| File | What it is |
|---|---|
| `RWFPostCheck/rules.py` | all the judgement. **No Fusion imports** — pure data in, findings out |
| `RWFPostCheck/shop_profile.json` | the shop constants. The only file to edit when the shop changes |
| `RWFPostCheck/RWFPostCheck.py` | entry point. Button registration only — **edit this and you must restart Fusion** |
| `RWFPostCheck/checkpost.py` | Fusion glue: live API → the dicts `rules.py` wants → dialog → post |
| `make_icons.py` | regenerates the button icon into `RWFPostCheck/resources/CheckPost/` |
| `RWFPostCheck/dumpparse.py` | parses Export Parameters dumps, so rules can be tested offline |
| `tests/test_rules.py` | runs the rules over real dumps |

Rules are kept free of `adsk` imports on purpose: code that only runs inside Fusion can never be asserted against. Keep it that way — new rules go in `rules.py` with a fixture, not in the glue.

```sh
python3 tools/fusion-addin/tests/test_rules.py
```

## Changing it

Edit `rules.py`, `checkpost.py` or `shop_profile.json` and **just click the button again** — the entry point re-imports the whole folder before every run, and the dialog title carries the version so you can see which code answered.

`RWFPostCheck.py` is the exception: Fusion caches the add-in module itself, so an edit there needs Stop/Run and sometimes a full restart. That is why it holds nothing but the button.

## Fixtures

Real Export Parameters dumps from the `arcdroid-coupons` document, 2026-10-22. Two are deliberately defective and are kept as regression cases:

- `op-other-holes-sketch-selected.txt` — `inputGeometry` reads `SketchCircle` on all four chains, but these were picked off the body. The sketch circles and the body's hole edges are coincident, so the field cannot tell a sketch pick from a body pick that resolved to the sketch underneath. **There is deliberately no rule on contour source** — this fixture is kept as the case that proved such a rule unusable. The condition that actually reverses hole direction is a setup with no model, which `job_model` catches unambiguously.
- `op-template-fresh.txt` — an operation straight from the `Plasma - Normal` template. Tool and comp are right, but cutting feed is 1000 mm/min: picking a tool resets the preset to `Default`. **Set the preset last.**

## Units

The Fusion API reports lengths in **centimetres** whatever the document is set to, feeds in mm/min, angles in degrees. `0.14` is 1.4 mm. `shop_profile.json` is stored in those same units so nothing converts at check time.

## What it does not check

Whether the contours selected are the ones the customer wanted; whether the controller is dialled to the setup sheet; consumables, clamping, material flatness. It validates settings, not intent.
